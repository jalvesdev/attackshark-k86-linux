# Correção de seleção da interface HID — ciclo 6

## Causa raiz

O enumerador hidapi retorna várias coleções HID para o mesmo par VID:PID. A implementação antiga calculava `wrong_interface` para todas as linhas do par e só então procurava correspondências que passassem por interface, usage page, usage e barramento USB. Se a lista de correspondências completas estivesse vazia, qualquer interface extra (por exemplo 0 ou 1) fazia a função lançar `IncorrectInterface`, mesmo quando o índice 2 também estava presente. Isso confundia ausência da interface alvo com falha em algum dos demais metadados.

Os dois registros em `docs/06-profile-hardware.jsonl` terminam em `IncorrectInterface` e não contêm `device`, `descriptor`, `identify_tx` nem `profile_tx`. Pela ordem do código de `tools/read_active_profile.py`, esse erro ocorreu dentro de `client.open()`, antes de abrir o path ou transmitir Feature Reports. Assim, não há evidência de que `0x8F` ou `0x85` tenham sido enviados nessas tentativas. O log não preserva as linhas brutas do hidapi, portanto não permite identificar retrospectivamente qual metadado da interface 2 fez o predicado antigo falhar, caso ela não correspondesse exatamente ao seletor.

## Correção

`select_device()` agora:

1. filtra as entradas pelo VID:PID suportado;
2. filtra as restantes pela interface exata 2;
3. exige nessa interface os mesmos uso HID `FFFF:0002` e metadado de barramento USB `1`;
4. recusa zero correspondências como dispositivo incorreto e mais de uma como ambígua.

A interface 0 ou 1 jamais é escolhida como fallback. VID:PID, número de interface, uso/coleção, barramento, descritor, identificação interna 1168 e família yc500 continuam protegidos nos mesmos estágios. Nenhum caminho `/dev/hidrawN` foi codificado e não houve consulta física durante esta correção.

## Regressões

Novos testes cobrem três interfaces `[0, 1, 2]` com somente a 2 compatível (inclusive via `K86Client.open()`, sem Feature Report), interface 2 ausente, múltiplos candidatos válidos para interface 2, VID:PID incorreto e coleção incorreta na interface 2. Suíte completa: **29 testes aprovados** com `.venv/bin/python -m unittest discover -s tests -v`.

## Repetição manual pendente

Após inspecionar a descoberta no Fedora, o procedimento físico autorizado continua sendo uma única identificação e uma única consulta de perfil, sem repetição automática:

```sh
.venv/bin/python tools/read_active_profile.py --timeout 2 --log docs/06-profile-hardware.jsonl
```

O script continua a validar seletor e descritor antes do identify, e exige ID 1168 antes de `0x85`. Não executar para testar a seleção apenas; não enviar qualquer outra operação.
